# 阶梯只保留真值档：不再探测「人机验证是否强制」

取代 [`0001`](0001-证据只能来自一次真实签到窗口.md) 与
[`0002`](0002-本机探针与浏览器取参的取舍.md) 里「阶梯按信息量排序、用未携带真凭证的
档位回答 `CaptchaEnforcement`」的那部分（0001 决定 3、0002 决定 3）。
其余结论一律保留：本机失败仍是弱证据、冲突时以手机端为准、真 Chrome + chromedp 取参、
归一化落盘纪律（不提交 HAR、只留「如何获取」）。

## 背景

原先的探针阶梯按「不需要人机 → 需要人机」排四档：
`code-check-in` / `captcha-verify-missing` / `captcha-verify-forged` / `captcha-verify-genuine`，
指望用「未携带真凭证的档位是否让到课记录增加」判 `CaptchaEnforcement`。

两轮真实窗口之后，这条线的性价比已经很差：

1. **前置档从未给出可判读的结果。** 缺参/伪造/遗留端点都只会拿到同一个
   `401 签到码不存在`（签到码校验先于风控），或者一个不可解释的拒绝；
   要判「不强制」只有「它成功了」这一种形态，属于单边证据（0001/0002 早已写明）。
2. **题目本身已经失去决策价值。** 现行前端只剩 `captcha-verify` 一条活着的签到路径，
   而它只在阿里云 SDK 出参之后才提交；`code-check-in` 在构建产物里零调用者。
   项目按「人机强制」运作即可，不需要再证一次。
3. **前置档是 F001 归因的混淆因子。** 它们在真值档之前几秒，向同一个 `userid`+`scene`
   打进去几次被风控拒的人机提交（`har#4` 实测：三次 `F001`），而真值档要回答的恰恰是
   「风控为什么不通过」。
4. **缺参档带着写入风险。** 若服务端**真的**不校验人机，那一档就是一次未鉴权的成功
   签到 —— 它会直接写入一条真实 `CheckInRecord`。拿它当「顺手也跑一下」的探针不合适。

## 决定

1. **按「人机强制」的前提运作**：活路径必须携带一份通过校验的 `captchaVerifyParam`。
   `CaptchaEnforcement` 不再是本工具要回答的问题。
2. **探针阶梯只保留真值档**（`captcha-verify-genuine`）。删除
   `code-check-in` / `captcha-verify-missing` / `captcha-verify-forged` 三个档位，
   以及只为它们存在的 `--ladder` / `--no-browser` / `--ladder-deadline` / `--sample-file`。
   工具的目的收敛成一句话：**验证库的 `SignIn` 封装路径可用，并取回一条活路径成功样本。**
3. **库侧一条不删**：`pkg/signin.Methods()` 里的 `analyze-a0` / `code-check-in` /
   `captcha-verify-missing` / `captcha-verify-forged` / `captcha-verify-genuine`
   都是给调用方的公开 API（README 有文档），根包的 `SignInLegacy` / `Analyze` /
   `ForgeCaptchaParam` 同样保留。变化只是**探针不再自动开火**。
4. **窗口预算随之变简单**：只剩一段真值档预算 + 等手机上报，不再有「前置档预算打不完
   就跳过」的分支。

## Considered Options

- **保留三档、但把默认取参改成只跑真值档**（例如默认 `--ladder genuine`）：否决。
  留一条「一键把混淆因子打开」的路径不值得，且缺参档的写入风险仍在代码里。
- **只保留 `captcha-verify-missing` 作为「一次知情冒险」**：否决。项目所有者已按
  「强制」运作；真要回头证伪，用 git 历史里的那一档 + 一次明确同意的窗口更干净。
- **连库侧 `Legacy` / `Analyze` / `ForgeCaptchaParam` 一起删**：否决。那是公开 API 的
  话题（README/docs 有文档、有单测），与「探针跑哪几档」是两件事。
- **把强制结论写成「已实测」**：否决。见下面 Consequence 第一条。

## Consequences

- **这不是证明。** 「人机强制」仍然只有单边证据（缺参 → `401` 不可解释）。
  文档里不得写成 ✅ 已实测；`docs/api.md` 与手册的措辞统一为「按强制前提运作」
  并指向本 ADR。
- **`docs/signin-probe.md` §0 的强判据表少了一条**：「未携带真凭证的档位让到课记录
  增加」不再可观测。剩下的强判据是「真值档成功（`T001`）」与「手机端权威样本」。
- **窗口更短更干净**：真值档之前不再有几次失败的人机提交，`F001` 的归属不再被搅浑。
- **想回头**：`git revert` 对应提交即可拿回那三档（含它们的测试与文档），
  但要先接受「有效码 + 缺失参数」可能直接写入一条真实考勤记录。
- 手册里「预置清单 / 演练判据」也随之简化：演练不再检查前置档的 `401`，
  只看真值档**有没有拿到 HTTP 状态**（拿不到就是 `transport_error`，链路没通）。
