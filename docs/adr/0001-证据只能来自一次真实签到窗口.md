# 证据只能来自一次不可重复、不可清理的真实签到窗口

判定 `CaptchaEnforcement`（服务端在写入考勤前是否要求一次通过校验的人机凭证）必须使用真实有效的 `SignInCode`：它由现场生成、有效期未知、无法事后复现，而实验本身会写入真实的 `CheckInRecord`。基于这个前提做了四个决定：

1. **唯一采集器是真机钉钉内 webview + 抓包代理**，不用模拟器或容器：真机路径已证明能解密全部阿里云侧请求，模拟器则要额外承担 SDK、定位与风控差异，引入无法归因的变量。
2. **探针请求一律在手机端改包重放**，不从其它机器发送，避免把客户端指纹与网络来源差异引进入结论。
3. **探针矩阵按「信息量 / 副作用」排序、预置并演练，且默认不写入**：只有当我们正要证明「不强制」时才允许出现额外记录，并在第一个写入成功的探针处停止。
4. **遗留端点探针只作单边证据**：`/checkIn/code-check-in` 与 `/ali-nvc/check-code-analyze` 在现行前端里分别是零调用者与不可达页面（后者还被传入了错误的参数），因此它们成功即证明不强制，失败则不可解释。

## Considered Options

- **安卓模拟器 / 容器化 Android**：否决。需要新建整套镜像与代理链，且桌面内核的设备指纹会与真机不同，无法判断失败来自服务端策略还是客户端差异。
- **由教师创建临时签到码、事后清理记录**：否决。依赖第三方配合，且事后清理会改写真实考勤数据，使采集到的那份证据失去可验证性。

## Consequences

- 实验不可重复：任何新问题都要等下一次真实窗口，探针失败也无法重试。因此文档必须显式记录「未证明」的项与原因，而不是留空或推测。
- 所有结论都要标注它是在哪一次采集里得到的，以及哪些变量未被隔离。
